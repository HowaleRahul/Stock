Implementation Plan: FrontPage-Style RL Self-Play Training
Goal
Transform the AI from a pattern memorizer (supervised learning on historical data) into a self-improving trader (reinforcement learning from its own live experience).

The model gets a virtual wallet with ₹10 Lakh, trades the live NSE market in real-time, keeps a detailed journal of every trade it takes (and every trade it rejects), and periodically reviews its own journal to update its beliefs about which setups work, in which regimes, and with what position sizing.

This is the same loop that makes FrontPage's TradeLab effective for human traders — except the "trader" is our AI.

Existing Infrastructure We Already Have
We are not building this from scratch. The codebase already has ~80% of the components:

What's Missing: The Closed-Loop Feedback
Right now, the paper trader trades → the journal logs → and then nothing happens. The ReinforcementLearner.batch_learn_from_journal() method exists, but it's only called manually. There is no automated loop that:

Periodically analyzes the journal
Identifies meta-patterns (e.g., "MACD is losing money in range-bound regimes")
Updates the model's prediction weights AND the setup confidence weights
Feeds these updated weights back into the next trading decision
Proposed Changes
Phase A: Historical Replay Engine (Fast Self-Play)
Purpose: Before going live, replay 5 years of historical candles through the virtual wallet at high speed to bootstrap the RL agent with thousands of simulated trades.

[NEW] ml/replay_engine.py
A new module that replays historical candles bar-by-bar through the full trading pipeline:


for each bar in historical_data:
    1. Feed bar to SetupEngine → get signals
    2. Feed signals to EnsembleModel → get AI prediction
    3. Feed prediction to RiskEngine → get trade plan (or rejection)
    4. If approved: open virtual trade in VirtualBroker
    5. Check all open trades for TP/SL/trailing/time exit
    6. Log everything to TradeLogger
    7. Every N trades: run JournalAnalyzer → update RL weights
Key design decisions:

No API calls during replay. All data is pre-downloaded and cached. This means we can replay 5 years in minutes, not months.
Realistic execution. Trades are filled at the next bar's open (not the signal bar's close) to prevent lookahead bias.
Transaction costs included. STT + slippage (0.05%) is deducted from every trade, just like the paper trader.
Multi-asset replay. Replay NIFTY, S&P 500, and BTC-USD sequentially so the RL agent learns across all asset classes.
Phase B: Journal Analyzer (The "Brain Review" Step)
Purpose: This is the core innovation — the AI reviews its own trade journal to learn meta-patterns that the supervised trainer misses.

[NEW] ml/journal_analyzer.py
A new module that reads the trade journal and computes actionable insights:

Setup Profitability Matrix: For each (setup × regime) pair, compute:

Win rate
Average PnL
Sharpe ratio
Average bars held
Consecutive loss streak
Failure Pattern Detection: Identify setups that are systematically losing money:

"MACD has a 35% win rate in range-bound regimes → suppress its confidence by 50%"
"RSI Divergence wins 80% in trending-bullish but only 20% in crash → gate it during crashes"
Position Sizing Feedback: Analyze whether the Kelly fraction is calibrated correctly:

"Average loss is 2.1x average win despite 65% win rate → the stop-losses are too wide"
"Probability of ruin exceeded 5% after 3 consecutive losses → reduce risk_per_trade from 2% to 1%"
Time-Based Patterns:

"Trades entered in the morning session (9:15-10:30) have a 72% win rate vs. 45% mid-day → weight morning entries higher"

Open Questions
IMPORTANT

Reward Function: Should the RL reward be raw PnL, risk-adjusted PnL (Sharpe), or a composite score? A composite like reward = sharpe - (max_drawdown_penalty) - (overtrading_penalty) is safest but hardest to tune. My recommendation is to start with raw PnL for simplicity and graduate to Sharpe after the first 500 trades.

IMPORTANT

Historical Replay Speed: During Phase A, should we replay 1 bar per second (for visual debugging) or as fast as possible (for bootstrapping)? I recommend maximum speed with a --slow flag for debugging.

WARNING

Model Reset: When we start the RL self-play loop, should we reset the existing supervised model weights (start fresh) or keep them and let RL fine-tune on top? My recommendation: keep the supervised weights as a warm start. The RL loop refines them, it doesn't replace them.
